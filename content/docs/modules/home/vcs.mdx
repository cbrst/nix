[`modules/home/vcs/`](https://github.com/cbrst/nix/tree/main/modules/home/vcs)
owns Git, [Jujutsu](https://github.com/jj-vcs/jj) (jj), and their terminal
interfaces. It is part of the [minimal profile](/profiles/home/#minimal).
For how these pieces are used day to day, see
[Working with jj](/workflows/jujutsu/).

## Git

Git uses the shared identity and rebases on `git pull`. A `prepare-commit-msg`
hook drafts commit messages with Claude Code; see
[Commit message drafting](/workflows/commit-messages/). The drafting command is
also installed as `claude-commit-draft`.

## Jujutsu

jj uses the same identity. Its editor is a small wrapper,
`jj-commit-editor`, which runs the same drafting hook in jj mode and then opens
`$EDITOR`. The draft description template includes the diff
(`builtin_draft_commit_description_with_diff`), which gives the hook something
to summarise.

### Aliases

| Alias | What it does |
| --- | --- |
| `jj logn` | Shows `trunk()..@` plus the parent of that range: a compact view of local, unpublished work |
| `jj pull` | Fetches from the Git remote, then rebases the mutable stack rooted at `roots(trunk()..stack(@))` onto `trunk()` |
| `jj push` | Fetches, rebases the local stack onto the remote bookmark if it gained commits, moves the nearest bookmark at or behind `@` forward to the newest described, non-empty commit at or behind `@`, then pushes only that bookmark with `-b exact:<name>`; see [How `jj push` decides](#how-jj-push-decides) for when it stops |
| `jj sync` | Runs `pull`, then pushes every bookmark in the current stack with `-b exact:<name>`, which also tracks new bookmarks on their first push; prints a message instead when the stack has no bookmarks |

`pull`, `push`, and `sync` run through `jj util exec` with `sh -c`, so the fetch,
rebase, and push run as one sequence that stops at the first failure. The
rebase source only moves the unpushed stack and leaves already-merged history
alone.

The scripts live in
[`modules/home/vcs/jj-aliases/`](https://github.com/cbrst/nix/tree/main/modules/home/vcs/jj-aliases)
as `pull.sh`, `push.sh`, and `sync.sh`. A `jjShellAlias` helper reads each one
with `builtins.readFile` at evaluation time and embeds it in the generated jj
config, so a new script must be visible to the flake's source snapshot.

### How `jj push` decides

`push` sorts and deduplicates the names of the bookmarks at or behind `@`, and
exits with status 1 and a message when there are none. It then runs
`jj git fetch` and looks for remote bookmark commits that are missing from the
history of `@`. Commits that were only rewritten locally, for example by
rebasing onto trunk, do not count as new. When there are new remote commits:

- If the remote bookmarks have diverged, `push` stops without moving anything
  and asks for a manual rebase.
- Otherwise it rebases the local stack onto the remote bookmark head.

If that rebase leaves conflicts in mutable commits, `push` stops before moving
bookmarks, prints the operation ID, and suggests `jj op restore <id>` to undo
the pull. Otherwise it moves the bookmark and pushes it.

The `stack(x)` revset alias is `reachable(x, mutable())`: the mutable commits
connected to `x`. `sync` pushes only bookmarks inside `stack(@)`, so bookmarks
on unrelated stacks are left alone.

## Zsh completion for jj

jj's dynamic completer only offers changed paths and matches them by literal
prefix, so a partial path such as `m/h/f` did not expand. The module adds a
wrapper, `_jj_with_files`, that loads jj's completer on first use, runs it, and
falls back to Zsh's `_files` when it returns no matches and the current word is
not a flag. The block is ordered at 1010 so it runs after the
[shell module's](/modules/home/shell/) initialisation.

## Terminal interfaces

- **LazyGit**, with shell integration, for Git repositories.
- **BlazingJJ**, for jj repositories.

Both are for shell use; Neovim has its own [VCS interface](/modules/home/neovim/#version-control).
