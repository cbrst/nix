Neovim is the default editor (`EDITOR=nvim`). The module lives in
[`modules/home/neovim/`](https://github.com/cbrst/nix/tree/main/modules/home/neovim)
and is imported by the [development profile](/profiles/home/#development),
so Asgard, Niflheim, and the templates all get the same setup.

## Ownership: Nix installs, Lua configures

There is no plugin manager such as Lazy.nvim, packer, or Mason, and nothing is
downloaded when Neovim starts.

- **Nix** owns the runtime surface. `spec.nix` is a plain function of `pkgs`,
  `lib`, `inputs`, the host's `settings`, the selected features, and a Claude
  Code package. It returns the unwrapped Neovim, every plugin and Tree-sitter
  grammar, the executables for Neovim's `PATH` (language servers, formatters,
  debuggers, search tools, and the Claude Code CLI), and the Lua configuration
  directory. The executables come from `tools.nix`, in named groups.
- **Lua** (`configs/init.lua` and `configs/lua/init6/`) configures what Nix
  installed.

Two wrappers consume the same definition, so neither redefines plugins or
tools:

| Wrapper | Output | Configuration |
| --- | --- | --- |
| `default.nix` | `programs.neovim` in Home Manager | Linked into `~/.config/nvim` as read-only store paths |
| `package.nix` | `packages.<system>.nvim` and `nvim-lite` | Bundled in the store and loaded through the wrapper's `-u` init file |

Adding a Lua `require` for a plugin that is not declared in Nix makes start-up
fail, so a new plugin, parser, server, or formatter is always added to
`spec.nix` or `tools.nix` first. Plugins missing from the pinned nixpkgs (NeoJJ,
codedocs, neo-tree file-nesting rules, and the generated palette and feature
plugins) are built locally from pinned sources. Lua must not assume
`~/.config/nvim`; it uses `vim.g.init6_config_dir or vim.fn.stdpath("config")`
when it needs the configuration directory.

The Python and Ruby providers are disabled.

### The init6 namespace

All hand-written Lua lives under `configs/lua/init6/` and is required as
`init6.*`, so it cannot collide with plugin modules that use generic names such
as `config` or `utils`. Only `init.lua` and `colors/init6.lua` sit outside it,
because Neovim looks them up by fixed paths.

| Name | What it is |
| --- | --- |
| `init6.generated.palette`, `init6.generated.features` | Lua modules that Nix generates, shipped as the `init6-palette` and `init6-features` plugins |
| `:colorscheme init6` | The theme, implemented in `init6.plugins.theme.colorscheme` |
| `init6-<purpose>` | Every autocommand group the configuration creates |
| `vim.g.init6_config_dir` | The bundled configuration path in the standalone packages |
| `:checkhealth init6` | The generated modules, the enabled features and languages, and whether the tools they need are on `PATH`; disabled features show as info |

## Features

`editor.neovim.features`, declared in `options.nix`, trims the editor per host.
Everything is on by default.

| Option | When disabled |
| --- | --- |
| `ai.enable` | No claudecode.nvim or Claude CLI, and no Claude statusline segment, dashboard key, or `<a-o>` picker action |
| `debug.enable` | No nvim-dap, DAP UI, virtual text, nvim-nio, one-small-step-for-vimkind, or debug adapters |
| `grammars` | `"all"` installs every grammar; a list of names from `vimPlugins.nvim-treesitter.builtGrammars` installs only those |
| `languages.<name>.enable` | No tools from that language group and no LSP or Conform setup for it; `web` also drops nvim-vtsls and nvim-ts-autotag |

The languages are `lua`, `markdown`, `nix`, `php`, `python`, `shell`, `web`, and
`yaml`. A host sets them like any Home Manager option, for example
`editor.neovim.features.languages.php.enable = false;`. Unknown names, wrong
types, grammar names missing from nixpkgs, and language lists that differ
between `options.nix` and `tools.nix` fail evaluation.

Nix passes the resolved values to Lua through the generated
`init6.generated.features` module, which `init6.config.features` reads as
`features.ai`, `features.debug`, and `features.language(name)`. Without the
module, as in an older installed generation, everything counts as enabled.
Servers and formatters of a disabled language are skipped without the "missing
tools" warning; only an enabled language whose server is not on `PATH` warns,
and the warning points at `:checkhealth init6`.

### Tool groups

`tools.nix` returns named package lists. `core` (`file`, `man-db`, `ripgrep`,
`mosh`, `sshfs`, `tree-sitter`) and `runtimes` (Bash, Lua, Node.js, Python 3, Zsh) are always
installed. Interpreters sit in `runtimes` because debug launches, Overseer
tasks, terminals, and language tooling all use them.

| Group | Contents |
| --- | --- |
| `debug` | debugpy, js-debug, bashdb with the Bash Debug adapter, and the local Lua debugger |
| `languages.lua` | lua-language-server, StyLua |
| `languages.markdown` | mdsf, rumdl |
| `languages.nix` | nil, nixd |
| `languages.php` | js-beautify (`html-beautify`), Mago, Phpactor |
| `languages.python` | Ruff, Zuban |
| `languages.shell` | bash-language-server, Shellharden, shfmt, zshcs |
| `languages.web` | Emmet, oxfmt, oxlint, the `oxlint-unused-imports` script, Some Sass, vtsls, vscode-langservers-extracted |
| `languages.yaml` | yaml-language-server, yamlfmt |

A package may appear in several groups; duplicates are removed. No
two distinct packages ship a command with the same name, so group order never
changes which executable a command resolves to. The Bash and Lua debug adapters
are taken from their VS Code extensions and wrapped in small scripts that run
them with Node.js.

Under Home Manager, `default.nix` also writes two global fallback files. A
project's own configuration always takes precedence.

- `~/.config/mago.toml`: PHP formatting with two-space tabs and double quotes.
- `~/.config/rumdl/rumdl.toml`: Markdown lines are reflowed to 80 characters,
  except code blocks, tables, headings, and math.

oxfmt has no global configuration, so projects without their own
`.oxfmtrc.json(c)` or `oxfmt.config.*` get the bundled `configs/oxfmtrc.json`
through `-c`. It enables `sortImports` and `sortTailwindcss`. Home Manager links
it to `~/.config/nvim/oxfmtrc.json`; the standalone packages bundle it with the
rest of the configuration.

## Standalone editor

The flake publishes the editor as two packages for `x86_64-linux` and
`aarch64-darwin`. They run on any machine with Nix, without Home Manager.

| Package | Features | Closure |
| --- | --- | --- |
| `nvim` | The defaults: everything | About 4.6 GiB |
| `nvim-lite` | Overrides from `lite.nix`: no AI or debugging, no PHP, Python, or web tooling, and 24 grammars for configuration, scripting, and VCS files | About 2.1 GiB |

```bash
nix run .#nvim -- file.txt                      # from a checkout
nix run github:cbrst/nix#nvim-lite -- file.txt  # from anywhere
```

`package.nix` wraps `spec.nix` with `wrapNeovimUnstable` the way Home Manager
does (executables appended to `PATH`, no Python or Ruby providers) and
evaluates `options.nix` with `lib.evalModules`, so the packages share the
defaults and type checks. How they differ from the Home Manager editor:

- The bundled configuration is loaded through `-u`; `~/.config/nvim` is never
  read. `vim.g.init6_config_dir` holds its path, and the Telescope "find file in
  Neovim config" mapping searches it.
- `NVIM_APPNAME` defaults to `init6`, so shada, undo, swap, and state stay apart
  from any other Neovim. Setting the variable overrides it. The wrapper creates
  `stdpath("data")` on start because a fresh machine lacks it.
- Theme and fonts come from the flake's `defaultSettings`, not a host's
  overrides.
- Claude Code is plain `pkgs.claude-code`, without the configuration from the
  [AI module](/modules/home/ai/).
- The Mago and rumdl fallback files are Home Manager files and are not written.

## Colour scheme

There are no third-party colour scheme plugins. The `init6` colour scheme
(`configs/colors/init6.lua`, implemented in `plugins/theme/colorscheme/`) builds
every highlight group from the palettes in `lib/themes.nix`. Nix generates an
`init6-palette` plugin that exposes the active [theme family](/architecture/settings-and-themes/)
to Lua as the `init6.generated.palette` module, and Home Manager installs the
colour scheme file through `xdg.configFile."nvim/colors"`. Control-flow keywords (`@keyword.conditional`, `.repeat`, `.return`,
`.exception`, `.import`, `.coroutine`) use their own `keyword_control` role,
apart from declaration keywords, and builtin variables and parameters have
roles of their own, fed by the optional palette slots described in
[Settings and themes](/architecture/settings-and-themes/). The Lua side blends
any shades the palette lacks from its slots, so every family gets the same
highlight structure. The command line has its own background (`bg_command`), the
darker of the palette's `shade0` and `shade2`, and the line number of the cursor
line takes the cursor line background. New plugins with their own highlight
groups get entries in `plugins/theme/colorscheme/groups/`. The Lua
configuration only chooses between the light and dark variant.

## Start-up order

Start-up is eager and ordered:

```text
init6.config.globals.setup()      leaders and capability flags
init6.options
init6.keymap
init6.autocmds
init6.languages.setup()           filetype behaviour
init6.plugins.setup()             explicit, ordered plugin groups
init6.config.theme.set_colorscheme()
```

The colour scheme is applied last because applying one clears the highlight
groups that Heirline and other UI plugins generate. Within the plugin groups,
leaders exist before any mappings, Mini Icons provides `nvim-web-devicons`
compatibility before its consumers load, VCS state is ready before the
statusline reads it, and Blink and LazyDev initialise before the LSP
configuration requests their capabilities.

## Editing features

| Area | Plugins and behaviour |
| --- | --- |
| Completion | Blink with LazyDev, LSP, paths, LuaSnip, and buffer sources; automatic command-line completion |
| Language servers | The `vim.lsp.config` / `vim.lsp.enable` API. Servers are enabled only when their executable exists: Bash, Emmet, JSON, Lua, Nix (`nil`), PHP (Phpactor), rumdl, Sass, YAML, Zsh (zshcs), and Python (Zuban). TypeScript and JavaScript use vtsls, a regular server in the `web` group, with nvim-vtsls (`:VtsExec`) and its buffer-local mappings (see below). nvim-ts-autotag closes and renames paired tags in HTML, JSX, Vue, Svelte, XML, and PHP |
| Formatting | Conform, on save: StyLua for Lua, mdsf then rumdl for Markdown, Ruff for Python, Shellharden then shfmt for Zsh, html-beautify then Mago for PHP, `oxlint-unused-imports`, oxlint, then oxfmt for JavaScript and TypeScript (including JSX and TSX), oxlint then oxfmt for Vue, oxfmt alone for CSS, SCSS, Less, HTML, JSON, JSONC, GraphQL, and TOML, oxlint alone for Svelte and Astro (oxfmt does not format them), and yamlfmt for YAML. Setting `vim.g.disable_autoformat` (or `vim.b.disable_autoformat` for one buffer) saves without running any formatter |
| Tree-sitter | Every grammar from nixpkgs. The SCSS grammar is patched and regenerated so it understands namespaced mixins and function calls |
| Import cleanup | `oxlint-unused-imports` deletes unused imports through oxlint's `no-unused-vars` suggestion fix and leaves unused locals, parameters, and functions alone. It runs apart from the oxlint step, because oxlint applies nothing when `--fix` and `--fix-suggestions` are combined, and repeats up to three times, because oxlint skips overlapping fixes such as adjacent import lines. Vue and Svelte are excluded: oxlint does not see their templates and would delete imported components |
| Debugging | nvim-dap with DAP UI and virtual text. Adapters for Python (debugpy), JavaScript and TypeScript (js-debug), Bash, standalone Lua, and Neovim Lua (one-small-step-for-vimkind). The Bash adapter is also offered for Zsh files but cannot interpret Zsh-only syntax |
| Annotations | codedocs.nvim generates documentation comments with `<leader>cA` |

## Interface

- **Heirline** draws the global statusline, including Git or jj diff counters.
- **Telescope** (Ivy layout) handles files, search, buffers, and LSP pickers.
  Its project root is the nearest `.jj` or `.git` directory. Find file and
  project search run ripgrep directly, so `.gitignore` rules apply even in
  non-colocated jj repositories. Dotfiles are shown and `.git` and `.jj` are
  always excluded. `<M-i>` in either picker reopens it with ignored files
  included, keeping the typed prompt. Live grep uses `telescope-live-grep-args`,
  so ripgrep flags can follow the quoted pattern (for example `"pattern" -t lua`
  or `-g *.nix`); `<C-k>` quotes the prompt and `<C-t>` quotes it and adds
  `--iglob`. Without the extension, live grep falls back to the stock picker,
  where `<C-Space>` refines results fuzzily. The start screen and the leader
  mappings use the same wrappers.
- **Neo-tree** shows the file system, buffers, Git status, and symbols, with
  file nesting and current-file following.
- **Snacks** provides input, picker, and terminal windows, the start screen
  (see below), and window dimming. Dimming is enabled at start-up and
  `<leader>td` toggles it. Terminal splits (`<leader>ot`, `oT`, `of`, and the
  remote shell) go on the right when the tab has a single column of windows
  and the code keeps at least 100 columns beside the terminal's 40% width,
  otherwise at the bottom. Fixed-width sidebars such as Neo-tree and Outline
  reduce the available width instead of counting as a column; other terminals,
  Claude Code included, count as one. A hidden terminal is placed again when
  it is shown, so it follows the layout at that moment.
- **Mini** adds text objects, surrounds, operators, pairs, indent scope, icons,
  and animation of the cursor, scrolling, window resizing, and window opening
  and closing. Cursor animation and the cursor line are disabled in terminal
  buffers because they made typing in TUIs lag. mini.operators keeps its
  evaluate, exchange, multiply, and sort mappings; its replace prefix is empty,
  so the `gr` replace operator is not mapped.
- **Line moves:** `<M-j>` and `<M-k>` move the current line down or up, or the
  selected lines in visual mode. Normal mode reindents the moved line with
  `==`, visual mode reindents the selection and reselects it, and insert mode
  leaves insert mode, moves the line, and returns with `gi`.
- **Which-key** shows the leader groups. Bindings follow the Doom Emacs layout.
- Dropbar, Outline, Trouble, todo-comments, render-markdown, and
  nvim-highlight-colors round out the UI.
- **Block brackets** (`plugins/ui/block-brackets.lua`) dim both ends of a
  bracket pair that sits on different lines, and a semicolon right after the
  closer (as in `});`), with the `Init6BlockBracket` highlight group, which uses
  the indent-guide shade. Pairs on one line, such as `(bar)` or `foo(1);`, keep
  their colours. Pairs come from the trees of the active Tree-sitter
  highlighter, so injected languages are covered and brackets in strings and
  comments are ignored; the marks are ephemeral and nothing is stored in the
  buffer. It is on by default; `vim.g.init6_dim_block_brackets = false` (for
  example in a project's `.nvim.lua`) turns it off and `<leader>tB` toggles it.
- **Auto Dark Mode** switches between the light and dark variant of the theme
  with the system appearance.

### Start screen

The Snacks dashboard (`plugins/ui/dashboard.lua`) is the start screen. It shows
a header modelled on Neovim's own `:intro` text, an action list, recent files,
and a random fortune.

| Key | Action |
| --- | --- |
| `f` | Find file |
| `g` | Search the project, from the VCS root when there is one |
| `r` | Recent files |
| `n` | New buffer |
| `s` | VCS status, labelled "jj status" or "Git status"; hidden outside a repository |
| `e` | File tree |
| `h` | Remote host: pick a host and mount it (see [Remote hosts](#remote-hosts)) |
| `c` | Claude Code; hidden when `claude` is not on `PATH` |
| `q` | Quit |

The action list is rebuilt on every render, so the VCS entry follows the
working directory. Recent files are limited to the current working directory,
and the block is hidden when there are none. The fortune is chosen once per
session, so resizing the window does not change it.

When the window is wide enough for two columns, a second pane runs the
`dashboard-pokemon` script, which prints a random
[pokemon-colorscripts](https://gitlab.com/phoneybadger/pokemon-colorscripts)
sprite centred against the height of the main pane. The script and
`pokemon-colorscripts` are on Neovim's wrapped `PATH`; if the script is not
found, the pane is omitted. The pane is not cached, so each launch shows a
different sprite. Indent scope and animation are disabled on the dashboard
buffer.

## Version control

Repository actions use **NeoJJ** in a jj repository and **Neogit** in a plain
Git repository. A colocated repository counts as jj, because `.jj` wins. The VCS
layer detects the root asynchronously, caches diff counters for the statusline
(unstaged tracked changes for Git, the working-copy commit `@` for jj), and
dispatches the shared actions:

| Mapping | Action |
| --- | --- |
| `<leader>gg` | Status |
| `<leader>gc` | Commit |
| `<leader>gd` | Diff |
| `<leader>gf` | Fetch |
| `<leader>gl` | Log |
| `<leader>gp` | Push |
| `<leader>gr` | Rebase |
| `<leader>gm` | Remotes |
| `<leader>gb` | Git branches or jj bookmarks |
| `<leader>gw` | Git worktrees or jj workspaces |

Empty jj description buffers opened from NeoJJ receive a Claude Code draft; see
[Commit message drafting](/workflows/commit-messages/#in-neovim).

The same actions are available as `:Vcs [action]`. Gitsigns hunk operations
live under `<leader>gh`, for example `<leader>ghp` to preview, `<leader>ghs` to
stage, and `<leader>ghr` to revert a hunk. **diffs.nvim** adds syntax-aware and
intra-line diff highlighting to Neogit, NeoJJ, Gitsigns previews, Telescope
previews, and conflict markers. Its own `:Diff` command only understands Git,
so the portable entry point is `<leader>gd`.

## Remote hosts

`plugins/ui/remote.lua` sets up remote-sshfs.nvim, which mounts an SSH host
under `~/.sshfs/<host>` so Neo-tree, Telescope, and the language servers see its
files as ordinary local paths. Hosts are listed from `~/.ssh/config`,
`~/.ssh/hosts`, and `/etc/ssh/ssh_config`; the plugin does not follow `Include`,
so the included host file is named explicitly. Hosts are chosen in a Telescope
picker, and connecting does not ask for a separate confirmation.

| Mapping | Action |
| --- | --- |
| `<leader>Rc` | Connect to a host |
| `<leader>Rd` | Disconnect, and return to the previous local directory if the working directory is on the mount |
| `<leader>Re` | Edit the SSH configuration |
| `<leader>Rf` | Find files on the host |
| `<leader>Rg` | Live grep on the host |
| `<leader>Rs` | Open a shell on the host in a terminal split |

Find and grep run on the host rather than through the mount, so they need `rg`
(or `fd`/`find`) there.

Mounts use `-o reconnect` with `ConnectTimeout=5`, `ServerAliveInterval=15`,
and `ServerAliveCountMax=3`. ssh exits about 45 seconds after the link dies and
sshfs reconnects, instead of file access, and with it the editor, blocking until
TCP times out. This list replaces the plugin's default sshfs options.

`<leader>Rs` uses the current connection, else the host whose mount holds the
working directory, else a picker of the SSH config hosts (wildcard patterns are
skipped). The terminal runs `mosh` and falls back to `ssh` when mosh cannot
start a session, for example when `mosh-server` is missing on the host. A
normal logout exits 0 and does not fall back. Without `mosh` on `PATH` it runs
`ssh` directly. The terminal starts in the home directory, because a working
directory on a stale mount would block the spawn.

A path counts as remote when it starts with the mount directory; the check
compares strings and never touches the mount. On those paths format on save,
Gitsigns, and the VCS context lookup are off, because Git status over SSHFS is
slow and a remote site is edited in place. Neo-tree's Git status is off while
the working directory is on a mount and follows the directory when it changes.

`sshfs` and `mosh` are in the `core` tool group. sshfs needs FUSE: NixOS provides
`fusermount`, while macOS needs macFUSE installed outside Nix.

## TypeScript

vtsls is a stdio server built on VS Code's TypeScript extension and bundles its
own TypeScript, so its semantic tokens match VS Code. `plugins/lsp/vtsls.lua`
sets up nvim-vtsls with mappings that are local to each buffer vtsls attaches
to:

| Mapping | Action |
| --- | --- |
| `<leader>co` | Organize imports |
| `<leader>cm` | Add missing imports |
| `<leader>cu` | Remove unused declarations |
| `<leader>cF` | Fix all |
| `<leader>cR` | Rename file |
| `gS` | Go to source definition |
| `<leader>cT` | Group: sort and remove unused imports, tsconfig, file references, TypeScript version, restart tsserver, reload projects, tsserver log |

Extract refactors start a rename. nvim-vtsls has no licence file, so nixpkgs
marks it unfree; `configLib.mkPkgs` allows that.

## Claude Code

[claudecode.nvim](https://github.com/coder/claudecode.nvim) runs the Claude Code
CLI in a right-side Snacks terminal and exposes the editor's context (open
files, selections, diagnostics) through its IDE bridge. The terminal is focused
and in insert mode as soon as it opens, and the leader mappings that open
terminals are normal-mode only so typing into Claude Code cannot trigger them.

| Mapping | Action |
| --- | --- |
| `<leader>oll` | Toggle Claude Code |
| `<leader>ola` | Add the file or selection to the context |
| `<leader>ols` | Pick a Claude Code action |
| `<leader>oln` | New session |
| `<leader>olc` | Select a model |
| `<leader>olr` | Ask Claude Code to edit the selection |
| `<leader>olR` | Review code |

Avante is still declared and configured as an inactive alternative; its setup
is disabled.

## Validating changes

The installed `nvim` runs the last activated configuration. To test Lua edits
in the checkout, load it explicitly:

```bash
nvim -n --headless \
  --cmd "set runtimepath^=$PWD/modules/home/neovim/configs" \
  -u "$PWD/modules/home/neovim/configs/init.lua" \
  '+qa'
```

That run uses the installed generation's plugins, so a generation older than
`init6.generated.palette` warns and falls back to the default colour scheme.
When plugins, executables, or theme values changed, run the standalone package,
which is built entirely from the checkout, against a scratch state directory.
Also run `nvim-lite` after changing feature-specific Lua or `spec.nix`, and open
files of the disabled languages; start-up and editing must stay free of errors
and "missing tools" warnings.

```bash
scratch="$(mktemp -d)"
env XDG_CONFIG_HOME="$scratch/config" XDG_DATA_HOME="$scratch/data" \
  XDG_STATE_HOME="$scratch/state" XDG_CACHE_HOME="$scratch/cache" \
  nix run '.#nvim' -- -n --headless path/to/real/file '+qa'
```

The Home Manager wrapper itself is tested with a built generation's pack
directory; the exact command is in
[`AGENTS.md`](https://github.com/cbrst/nix/blob/main/AGENTS.md#neovim-validation-before-activation).
Format changed Lua with `stylua`.
