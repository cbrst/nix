## Nautilus

The NixOS side installs Nautilus with GVfs (see
[desktop modules](/modules/nixos/desktop/#nautilus)). The Home Manager
module in
[`modules/home/nautilus/`](https://github.com/cbrst/nix/tree/main/modules/home/nautilus)
adds a Python extension with two context-menu actions for a single selected
item:

| Selection | Action |
| --- | --- |
| A folder | **Open Folder as Slideshow**: plays every image and video in it, recursively and shuffled, full screen in mpv, five seconds per image |
| An image | **Set as Noctalia Wallpaper**: converts it to `~/Pictures/Wallpapers/wallpaper.jpg` and tells Noctalia to use it |

Both actions are shell scripts packaged with `writeShellApplication`, and their
store paths are substituted into the extension. The wallpaper script lives in
[`packages/set-noctalia-wallpaper`](https://github.com/cbrst/nix/tree/main/packages/set-noctalia-wallpaper),
shared with imv. The wallpaper action appears only when `programs.noctalia` is
enabled. The extension starts them as
Gio subprocesses and waits for them asynchronously, so a failure to start or a
non-zero exit is reported through GLib instead of being lost. The wallpaper
script sends a desktop notification on failure. Because Noctalia caches images
by path, it first shows a staged copy and then the final file.

The extension is linked as a directory (a `linkFarm` holding
`context_actions.py`, placed at `nautilus-python/extensions`) rather than as a
single file. Python cannot write a `__pycache__` beside a module in the Nix
store, so it never reuses a stale `.pyc` from an older generation, which could
otherwise pass the staleness check (store files have an mtime of 1) and keep
calling old helper paths.

## imv and mpv

- **imv** is the image viewer, with its background set to the theme's dark
  background colour. When `programs.noctalia` is enabled, `w` runs
  `set-noctalia-wallpaper` on the current image in the background, because imv
  waits for exec commands and its key repeat would otherwise re-run the slow
  conversion. The script takes a non-blocking lock, so overlapping runs (key
  repeat or Nautilus) exit instead of racing on the staging and destination
  files.
- **mpv** is the video player, with the [uosc](https://github.com/tomasklaen/uosc)
  interface.

## Helium

[`modules/home/helium/`](https://github.com/cbrst/nix/tree/main/modules/home/helium)
installs the Helium browser from the NUR package and generates a Vimium-C
settings backup at `~/.config/vimium-c/settings.json`.

Vimium-C cannot read a configuration file, so the JSON is a backup to import by
hand through its options page (Backup/Restore). It carries:

- key mappings and search engines, from plain text files with one entry per
  line that Nix splits into arrays;
- a user CSS theme rendered from the light and dark palettes of the selected
  [theme family](/architecture/settings-and-themes/);
- smooth scrolling, next/previous link patterns, and an exclusion rule for
  Monkeytype.

The backup's `time` field is set above 10000 because Vimium-C rejects files
whose modification time looks like the Nix store epoch of 1. `mappings.txt`
records the Tridactyl bindings that were not ported, such as the yt-dlp and
wallhaven features, which need capabilities Vimium-C lacks.
