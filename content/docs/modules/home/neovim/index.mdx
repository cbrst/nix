Neovim is the default editor (`EDITOR=nvim`). The module lives in
[`modules/home/neovim/`](https://github.com/cbrst/nix/tree/main/modules/home/neovim)
and is imported by the [development profile](/profiles/home/#development),
so Asgard, Niflheim, and the templates all get the same setup. The same
definition is also published as the standalone `nvim` and `nvim-lite`
packages.

## Nix installs, Lua configures

There is no plugin manager such as Lazy.nvim, packer, or Mason, and nothing is
downloaded when Neovim starts. The work is split in two layers that meet at a
few well-defined points:

- **Nix** decides what exists: the Neovim binary, every plugin and Tree-sitter
  grammar, every executable on the editor's `PATH`, and two generated Lua
  modules that describe the build (the theme palette and the enabled
  features).
- **Lua** decides how it behaves. It configures what Nix installed, and reads
  the generated modules to know what it may set up.

```text
                         lib/themes.nix        options.nix
                               │                    │ editor.neovim.features
                               ▼                    ▼
 tools.nix ──────────────▶ spec.nix ◀───────── lite.nix (nvim-lite only)
                               │
        ┌──────────────────────┼──────────────────────────┐
        ▼                      ▼                          ▼
  package               plugins + grammars          extraPackages
  neovim-unwrapped      incl. init6-palette,        LSP servers, formatters,
                        init6-features              adapters, claude, …
        └──────────────┬───────┴──────────────┬───────────┘
                       ▼                      ▼
                 default.nix             package.nix
               programs.neovim        wrapNeovimUnstable
               ~/.config/nvim ◀─┐  ┌─▶ bundled store path, -u
                                │  │
                          configs/ (init.lua, lua/init6/, colors/)
```

[Packaging](/modules/home/neovim/packaging/) describes the Nix side and
[Features](/modules/home/neovim/features/) how a host switch travels from
`options.nix` into the Lua code.

## The init6 namespace

The configuration is branded *init6*. All hand-written Lua lives under
`configs/lua/init6/` and is required as `init6.*`, so it cannot collide with
plugin modules that use generic names such as `config` or `utils`. Only
`init.lua` and `colors/init6.lua` sit outside it, because Neovim looks them up
by fixed paths.

| Name | What it is |
| --- | --- |
| `init6.generated.palette`, `init6.generated.features` | Lua modules that Nix generates, shipped as the `init6-palette` and `init6-features` plugins |
| `:colorscheme init6` | The theme, implemented in `init6.plugins.theme.colorscheme` |
| `init6-<purpose>` | Every autocommand group the configuration creates |
| `vim.g.init6_config_dir` | The bundled configuration path in the standalone packages |
| `vim.g.init6_dim_block_brackets` | Turns the [block-bracket dimming](/modules/home/neovim/interface/#block-brackets) off when `false` |
| `:checkhealth init6` | The generated modules, the enabled features and languages, and whether the tools they need are on `PATH` |

Inside the namespace, `config/` holds shared editor policy and state,
`plugins/<group>/` holds plugin setup and orchestration, `languages/` holds
filetype behaviour, and `utils/` holds generic helpers such as the shared icon
table. Every plugin group exposes `M.setup()` and is called from an explicit,
ordered list rather than discovered at run time.

## Shared helpers that tie modules together

A few modules are called from many places; changing them affects more than
their own feature.

| Helper | Called by |
| --- | --- |
| `init6.config.features` | Plugin loader, smart loader, LSP, formatting, Tree-sitter, Heirline, Snacks, dashboard, health |
| `init6.plugins.ui.vcs` (`context`, `get`, `open`) | Heirline, Telescope project root, dashboard, `<leader>g` mappings, `:Vcs` |
| `init6.plugins.ui.remote` (`contains`) | VCS context, Gitsigns, Conform format on save, Neo-tree Git status |
| `init6.plugins.ui.snacks` (`terminal`) | Terminal mappings and the remote shell |
| `init6.plugins.ui.telescope` (`find_files`, `live_grep`) | Leader mappings and dashboard |
| `init6.config.theme` (`set_colorscheme`) | `init.lua` and Auto Dark Mode |
| `init6.config.ui_colors` | Theme application and every Heirline segment |
| `init6.utils.icons` | Options (fold markers), diagnostics signs, debugger signs, Heirline |
